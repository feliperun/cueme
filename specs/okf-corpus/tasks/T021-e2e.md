## Objetivo

Dois cenários `CueMeUITests`. O primeiro é **o único teste que prova a premissa
inteira da refatoração**: editar o Markdown por fora e ver a mudança na UI. Se ele
não existir, nada garante que o corpus é de fato editável fora do CueMe.

## Contexto obrigatório

  de acessibilidade estáveis, nunca sleeps.**

## Decisões já tomadas

- Nova variável de ambiente `CUEME_UI_CORPUS_ROOT`: quando setada, o app usa um
  corpus real naquele diretório em vez de `UITestFixtures.memory`, e o reload volta
  a ficar ligado. Quando não setada, o comportamento atual continua idêntico —
  inclusive o guard.
- O teste escreve o `.md` direto no disco, com `String.write(to:)`. Não use o app
  para produzir a edição: a graça é justamente ser externa.
- Sem `sleep`. Use `waitForExistence` sobre identificadores estáveis.

## Cenários

**`testExternallyEditedNoteMarkdownWinsInTheUI`**
1. Sobe o app com `CUEME_UI_CORPUS_ROOT` num diretório temporário contendo uma nota
   com uma pendência não marcada.
2. O teste reescreve o `.md` em disco: título diferente, `- [ ]` virando `- [x]`.
3. Dispara o reload (ativação da janela).
4. Assere que a biblioteca mostra o título novo e o painel mostra a pendência
   marcada.

**`testNestingANoteMovesItOnDisk`**
1. Sobe com dois irmãos na raiz.
2. Arrasta um sobre o outro pela árvore.
3. Assere que a UI mostra aninhado **e** que o `.md` está em `<pai>/<filho>.md`.

## Critérios de aceite (EARS)

- **AC1** — QUANDO o `.md` é editado no disco e o app reativa, O SISTEMA DEVE
  mostrar o título novo na biblioteca.
- **AC2** — QUANDO uma pendência é marcada no disco, O SISTEMA DEVE mostrá-la
  marcada no painel.
- **AC3** — QUANDO uma nota é aninhada pela UI, O SISTEMA DEVE movê-la em disco para
  dentro da pasta do pai.
- **AC4** — QUANDO `CUEME_UI_CORPUS_ROOT` não está setada, O SISTEMA DEVE se
  comportar exatamente como antes, guard incluído.
- **AC5** — QUANDO uma sessão ao vivo termina, O SISTEMA DEVE deixar a nota e
  `raw/transcript.md` sobreviverem ao reload.

## Verificação

```bash
xcodebuild -project CueMe.xcodeproj -scheme CueMe -destination 'platform=macOS' build CODE_SIGNING_ALLOWED=NO
xcodebuild -project CueMe.xcodeproj -scheme CueMe -destination 'platform=macOS' -skip-testing:CueMeUITests test
xcodebuild -project CueMe.xcodeproj -scheme CueMe -destination 'platform=macOS' -only-testing:CueMeUITests test
sentrux check . && sentrux gate .
```

O runner de UI pode falhar por ambiente numa máquina de dev, com
`Timed out while enabling automation mode`. Isso é falha de ambiente, não do teste:
verifique contra um checkout limpo antes de culpar o diff, e **reporte** em vez de
tentar contornar. O job `ui-e2e` do CI é o gate.
